# Quality checks

From the repository root:

```sh
make tools
make check
```

`make tools` installs `cargo-llvm-cov` 0.9.1 and `cargo-audit` 0.22.2 into the ignored `target/tools` directory. It also ensures Clippy, rustfmt, and `llvm-tools-preview` are installed for the active Rust toolchain. It does not change the selected toolchain or global version pins. The Makefile adds the local CLI directory to PATH only for its commands.

## Defaults and scope

| Target | Command | Policy |
| --- | --- | --- |
| `make fmt` | `cargo fmt --all -- --check` | Default formatting; fails on differences. |
| `make lint` | `cargo clippy --locked --all-targets -- -D warnings` | Default Clippy lints; warnings fail. No blanket pedantic/restriction groups. |
| `make coverage` | `cargo llvm-cov --locked --no-default-features --test preview_gate --html` | Runs the projection integration check; produces a report with no percentage threshold. |
| `make audit` | `cargo audit --db target/audit-db` | Default RustSec policy: known vulnerabilities fail, informational maintenance warnings remain visible and nonfatal. No advisory ignore list. |

`make check` runs those four targets and stops on failure. The RustSec database cache and generated reports live under ignored `target/` paths.

Coverage measures `src/lib.rs`, not the GPUI window in `src/main.rs`. The public-API check lives in `tests/preview_gate.rs`; test/example source is excluded by cargo-llvm-cov's default reporting rules. Stable line/region coverage is enabled; branch coverage is not enabled. The native gate still runs separately with `cargo run --locked --example viewer_gate` and is not included in this coverage figure.

Open the generated report at **`target/llvm-cov/html/index.html`**. It is regenerated by `make coverage`, not committed.

## Baseline: 2026-10-06

`make check` passes on the development Mac with Rust 1.96.0. Reported library coverage, excluding test assertions:

| Metric | Covered / total | Percentage |
| --- | --- | --- |
| Lines | 275 / 311 | 88.42% |
| Regions | 397 / 433 | 91.69% |
| Functions | 20 / 21 | 95.24% |

Useful uncovered cases include non-regular/oversized-file rejection, processor-panic fallback, character references, unlabeled web links, and explicit line breaks. Treat these as a test-planning aid, not a reason to write tests solely for a percentage. Coverage does not establish source preservation, security, or GUI usability by itself.

Inverse dependency-tree inspection traces all seven through GPUI's dependency graph. The audit covers the whole lockfile, including target-specific dependencies, rather than only currently executed code. No packages were upgraded, forked, or suppressed to hide these warnings; reassess the toolkit/dependency chain before production use. Cargo also reports the existing upstream future-incompatibility warning for `block` 0.1.6.

For a specific warning, inspect its owner with `cargo tree --locked --target all --invert CRATE`. After generating coverage, inspect missed lines without rerunning tests:

```sh
PATH="$PWD/target/tools/bin:$PATH" cargo llvm-cov report --locked --show-missing-lines
```

Numerical complexity reporting and CI-host-specific workflows are deferred. Clippy's default complexity checks are active; add separate metrics when there is a concrete need to track hotspots or trends.
